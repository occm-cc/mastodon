# 예약 게시물 개발 계획

작성일: 2026-10-11

사용자 확정 사항: API 호환성을 위해 기존 V1 API를 유지하고, 웹 예약 기능은 새 `/api/v2/scheduled_statuses` API로 구현한다.

## 목표와 사용자 흐름

redesign 게시글 작성창의 언어 선택 버튼을 예약 버튼으로 교체한다. 새 게시물의 언어는 사용자 인터페이스 언어를 사용한다. Bird UI의 트위터와 비슷한 외형과 기존 인라인 작성 흐름을 유지하면서, 예약 설정 → 예약 생성 → 목록 조회 → 기존 작성창에서 편집 → 예약 취소까지 제공한다.

참고 화면:

- [예약 설정](https://fanbinit.us/files/attach/filebox/2026/10/11/78f56f2cdd5b556adceb125ca0abaeca.png)
- [예약 목록](https://fanbinit.us/files/attach/filebox/2026/10/11/958feeaa6ab6003c5a853643805d7ef4.png)

사용자 흐름은 다음과 같다.

1. 작성창의 기존 언어 버튼 위치에 있는 달력 버튼을 누른다.
2. 예약 설정 화면에서 날짜, 시간, 시간대를 확인하고 **확인**을 누른다. 이 동작은 작성창에 예약 시간을 적용한다.
3. 작성창에 전송 예정 시각이 표시되고 제출 버튼이 **예약하기**로 바뀐다. 이를 누르면 서버에 예약이 저장된다.
4. 예약 설정 화면 하단의 **예약 게시물**을 누르면 예약 목록이 열린다. 본문이 비어 있어도 목록에 접근할 수 있다.
5. 목록의 게시물을 누르면 기존 작성창에 내용과 예약 시간이 복원된다. 수정 후 **예약 변경 저장**을 누르면 같은 예약이 갱신된다.
6. 목록의 **수정** 모드에서는 예약을 선택해 취소할 수 있다. 취소 전 기존 확인 모달을 이용한다.

예약 설정의 **확인**과 서버에 저장하는 **예약하기**를 구분한다. 설정 화면을 닫기만 하면 변경 전 작성 상태로 돌아간다. 신규 작성 중 예약 시간만 해제하면 즉시 게시 방식으로 돌아가며, 저장된 예약의 취소는 명시적인 별도 동작으로 처리한다.

## 코드 조사 결과와 재사용 범위

| 기능                | 현재 구현                                                                              | 작업 방향                                                     |
| ------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 예약 생성           | `POST /api/v1/statuses`의 `scheduled_at`, `PostStatusService`                          | 기존 서비스 검증 재사용, 생성은 새 V2 API                     |
| 조회·시간 변경·취소 | `/api/v1/scheduled_statuses`, `ScheduledStatusesController`                            | 기존 엔드포인트 유지, 새 V2 API 제공                          |
| 예약 본문 편집      | 현재 PUT은 `scheduled_at`만 허용                                                       | 동일 예약 ID를 유지하는 원자적 내용 수정 추가                 |
| 실제 발행           | `ScheduledStatusesScheduler`, `PublishScheduledStatusWorker`                           | 기존 작업 유지, 변경된 예약 시간 재검사와 동시 실행 처리 보완 |
| 게시글 작성 UI      | `RedesignComposeForm`, `ComposeTextarea`, 첨부·투표·공개 범위 컴포넌트                 | 예약 편집에도 그대로 사용                                     |
| 모달·입력·버튼      | `ModalRoot`, `ModalShell`, `SelectField`, `TextInputField`, redesign `Button`          | 기존 접근성·테마·포커스 처리 재사용                           |
| 언어                | 초기 상태의 `default_language`는 `preferred_posting_language`, UI 언어는 `meta.locale` | UI 언어를 명시적으로 적용                                     |
| 언어 변경 유도      | `ComposeHints`의 언어 추정과 변경 버튼                                                 | 고정 언어 정책에 맞게 제거                                    |
| 작성 중 내용 보호   | `COMPOSER_DRAFT_DELETE`, 작성창 열기·닫기 로직                                         | 예약 편집 진입에도 재사용·확장                                |

예약 테이블과 발행 시스템이 이미 있으므로 별도의 예약 저장소나 타이머, 새로운 작성 에디터를 만들지 않는다. 새 코드의 중심은 예약 UI, API 응답 타입, 예약 편집 상태 및 기존 서비스의 수정 지원이다. 현재 미커밋 DM 헤더 수정은 이번 작업 중 보존한다.

## 적용 범위와 동작 정책

### 언어

- redesign의 일반 새 게시물, 답장, 인용, 새로 작성하는 예약 게시물은 UI 언어를 사용한다. 답장 대상의 언어가 작성 언어를 덮어쓰지 않도록 한다.
- 언어 선택과 언어 변경 제안을 제거한다. 버튼만 숨기고 기존 언어 변경 경로가 남는 상황을 방지한다.
- UI locale에 지역 코드가 있으면 기존 `LanguagesHelper`의 지원 언어 규칙에 따라 처리한다. 지원하지 않는 locale의 fallback도 같은 규칙을 사용한다.
- 기존 게시물 및 이미 저장된 예약의 편집은 원래 언어를 보존하는 정책으로 계획한다. 내용을 수정하는 것만으로 과거 게시물의 언어가 바뀌는 일을 방지하기 위한 예외다.
- 다른 API 클라이언트가 보내는 `language`는 계속 지원한다. 이 변경은 웹 작성창의 정책이다.

### 예약과 시간

- 기존 서버 규칙대로 현재로부터 **5분 초과**의 시간을 허용한다. 안내 문구와 클라이언트·서버 경계 검사를 일치시킨다.
- 날짜는 월·일·년, 시간은 시·분·AM/PM으로 구성해 참고 화면의 구성을 따른다. 기존 `SelectField`를 사용하고 달력 선택이 필요하면 브라우저의 날짜 입력을 연결한다.
- 브라우저 시간대의 이름과 전송 예정 시각을 표시한다. 서버에는 UTC ISO 시각을 보낸다. 존재하지 않는 날짜, DST 전환으로 유효하지 않은 시간과 중복되는 시간의 처리 방식을 테스트한다.
- 기존 API는 과거의 `scheduled_at`을 즉시 발행으로 처리할 수 있다. 기존 API의 이 동작은 유지한다. 새 V2 API만 유효하지 않은 시간에 오류를 반환해 의도치 않은 즉시 게시를 막는다.
- 전체 300개·일별 25개라는 기존 제한을 유지한다. 기존 예약 수정 시 자기 자신이 제한에 중복 계산되지 않도록 한다.
- 이미 발행된 게시물을 편집할 때는 예약 버튼을 제공하지 않는다.
- 일반 Status API로 작성하는 게시물의 기존 첨부·투표·답장·인용·공개 범위를 지원한다. `/direct_message`의 별도 채팅 작성창에는 적용하지 않는다.

### 예약 목록과 편집

- 첫 버전의 관리 화면은 요청한 **예약 게시물** 목록이다. 참고 이미지의 ‘전송하지 않은 게시물’ 탭에 해당하는 별도 초안 저장 기능은 후속 범위로 둔다.
- 예정 시각이 가까운 순서로 표시하고, 본문 미리보기·첨부 여부·예약 시각을 제공한다. 빈 목록, 로딩, 오류·재시도를 제공한다.
- 기존 API의 ID 기반 페이지네이션을 그대로 사용한다. 전체 예약 수 상한이 300개이므로 `Link`를 따라 목록을 가져온 후 예정 시각·ID로 정렬한다. 첫 페이지 안에서만 정렬해 전체 순서가 틀어지지 않도록 한다.
- 목록 열기 자체는 현재 작성 중인 내용을 바꾸지 않는다. 다른 예약의 편집으로 전환할 때 작성 중인 내용이 있으면 기존 확인 흐름을 거친다.
- 본문, CW, 민감한 미디어 표시, 공개 범위, 첨부 순서·설명·초점, 투표, 답장·인용 맥락, 인용 허용 정책, 예약 시간을 복원한다.
- 편집창에서 변경한 값은 저장 성공 후에만 서버 예약에 반영된다. 취소·실패하면 기존 예약은 유지한다. 예약을 삭제한 다음 새 예약을 만드는 방식은 사용하지 않는다.
- 수정 중 다른 탭에서 취소되거나 발행되어 404가 발생하면 상태를 안내하고 목록을 갱신한다. 작성 중인 내용은 즉시 지우지 않는다.
- 계정별 목록과 편집 상태를 분리한다. 계정 전환·로그아웃 후 이전 계정의 예약을 노출하거나 제출하지 않는다.

## 개발 단계와 완료 기준

각 단계는 관련 검증을 마친 후 다음 단계로 진행한다. 계획 조사와 API 분리 방침을 확정했고, 아래 순서로 구현과 검증을 진행한다.

### 1단계 — 예약 수정 API와 발행 작업 보완

작업:

- 새 `/api/v2/scheduled_statuses`에 생성·조회·내용 수정·취소를 제공한다. 기존 V1 엔드포인트의 요청·응답 계약과 과거 날짜 처리 동작은 유지한다.
- 생성·수정에 공통으로 필요한 검증과 옵션 정규화는 `PostStatusService`에서 공유 가능한 부분을 추출해 재사용한다. 본문·첨부·투표 등의 검증을 별도로 복제하지 않는다.
- 필드 누락은 기존 값 유지, 명시적인 빈 값은 삭제로 구분한다. 공개 범위·답장·인용 권한, 미디어 소유권 및 다른 게시물·예약에 사용 중인 미디어를 검증한다.
- 같은 예약 레코드를 잠그고 내용·미디어 연결·시간을 트랜잭션으로 갱신한다. 예약 취소와 발행 작업도 같은 잠금 규칙을 사용한다.
- 이미 큐에 들어간 작업이 실행될 때 DB의 최신 예약 시간을 다시 확인한다. 뒤로 미룬 예약을 옛 시각에 발행하지 않고, 앞으로 당긴 예약도 기존 스케줄러가 처리하도록 한다.
- 실제 게시물 저장과 예약 소비가 일관되도록 처리한다. DB 롤백 시 예약 손실, 작업 중복 실행 시 중복 발행을 막고 게시물 배포·알림 작업의 실행 시점도 검토한다.
- 날짜 오류와 수정 시 제한 계산을 보완하고 API 확장 사항을 기록한다.

완료 기준:

- 동일 ID로 본문·시간·첨부를 변경할 수 있다. 다른 계정의 예약·미디어에 접근할 수 없다.
- 잘못된 수정은 기존 예약과 미디어 연결을 바꾸지 않는다.
- 이전 시간에 큐에 들어간 작업, 반복 실행, 취소된 예약, 발행 시각 근처의 수정·취소를 다루는 요청·서비스·worker 테스트가 통과한다.
- 기존 시간 변경·생성·발행 동작의 회귀 테스트가 통과한다.

### 2단계 — 언어 고정과 작성 상태·API 연결

작업:

- UI locale을 새 게시물의 언어로 적용하고 답장·인용·초기화·계정 전환 경로를 정리한다. 기존 게시물 편집의 언어 보존을 검증한다.
- 일반 게시물 ID와 별개인 `scheduled_status_id`, `scheduled_at`을 기존 compose 상태에 추가한다. 초기화·전환 시 이전 예약 상태를 제거한다.
- 예약 응답 타입과 기존 API 래퍼를 추가한다. 제출은 일반 생성, 예약 생성, 일반 편집, 예약 편집으로 분기한다.
- 예약 응답은 `Status`가 아니므로 타임라인 삽입·게시물 상세 링크·일반 게시 성공 알림을 실행하지 않는다. 예약 성공 알림과 목록 갱신을 연결한다.
- 기존 제출 검증, 대체 텍스트 확인, CW·인용 확인 모달과 재시도 시 초안 보존을 유지한다.
- 예약 성공 후 초기화와 standalone 작성 페이지의 이동 동작을 처리한다. 예약 응답에 게시물 URL이 있다고 가정하지 않는다.

완료 기준:

- UI 언어와 게시 언어 기본 설정이 달라도 새 게시물은 UI 언어를 사용한다.
- 예약 생성·수정 응답이 일반 게시물 저장소와 타임라인에 들어가지 않는다.
- 예약 상태 초기화, API 실패 후 작성 내용 보존, 일반 즉시 게시·기존 게시물 편집 테스트가 통과한다.

### 3단계 — 트위터 형태의 예약 설정 UI

작업:

- 기존 언어 버튼 자리에 달력 아이콘의 예약 버튼을 넣는다.
- 기존 모달 구조로 닫기·제목·우측 확인 버튼, 전송 예정 요약, 날짜·시간 선택, 시간대, 하단 예약 게시물 링크를 구성한다.
- 설정 화면 내 변경값은 로컬 상태로 두고 **확인**할 때 compose 상태에 반영한다.
- 작성창의 예약 요약, 예약 시간 변경·해제, **예약하기** 버튼을 연결한다.
- 새 모달이 기존 작성 `<form>` 안에 중첩되지 않도록 `ModalRoot`를 사용한다.
- Bird UI의 색·간격·테두리·버튼 스타일과 native 테마의 기존 토큰을 사용한다. 모바일에서는 화면 폭과 키보드·하단 탐색 영역을 고려한다.

완료 기준:

- PC 홈 인라인 작성창, standalone 작성 페이지, 모바일 작성창에서 같은 예약 흐름이 동작한다.
- 닫기·Escape로 작성 내용이나 예약이 저장되지 않으며 확인 후에만 선택이 반영된다.
- 유효하지 않은 시간 안내, 버튼 상태, 키보드 조작·포커스 복귀를 브라우저에서 확인한다.

### 4단계 — 예약 목록·내용 편집·취소

작업:

- 예약 설정 화면의 하단 링크와 예약 성공 알림에서 관리 목록을 연다.
- 서버 목록 조회, 전체 순서 정렬, 미리보기, 새로고침, 빈 목록·오류 상태를 추가한다.
- 예약 선택 시 기존 작성 상태 보호 확인을 거쳐 동일 작성창에 예약 내용을 복원한다. 예약 편집 제목과 **예약 변경 저장** 버튼을 제공한다.
- 기존 예약 편집에서 닫기는 미저장 변경의 취소로 처리한다. 서버 예약을 삭제하지 않는다.
- 목록의 수정 모드와 선택 취소 동작을 구현한다. 여러 항목 취소 시 일부 실패한 예약은 목록에 남기고 결과를 안내한다.
- 성공 후 목록·작성창 상태를 동기화하고 계정 전환 및 오래된 응답을 처리한다.

완료 기준:

- 시간·본문·첨부·투표 등 지원 필드가 복원되고 같은 예약 ID로 저장된다.
- 작성 중 다른 예약 선택, 저장 실패, 편집 취소, 일부 취소 실패, 이미 발행된 항목의 편집을 처리한다.
- 다음 페이지의 더 이른 예약도 올바른 순서에 표시되고 계정 간 상태가 섞이지 않는다.
